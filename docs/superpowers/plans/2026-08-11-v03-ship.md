# Ship v0.3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close out the v0.3 ergonomics track — a synthesis REPORT, a
corrected README results section, and a SPEC version bump — so the
project can pivot to the fine-tune track against a documented baseline.

**Architecture:** Three documentation tasks, no code. Every figure is
read from committed data or a committed REPORT, and each task re-derives
its own figures with the commands given rather than copying them from
this plan on trust. The annotated `v0.3` tag is **not** a task here: it
is created after this branch merges to `main`, in the
finishing-a-development-branch step.

**Tech Stack:** Markdown; `python -m eval.g0_report` and
`python -m eval.deformation` for figure re-derivation; `pytest` for the
regression gate.

**Source spec:** `docs/superpowers/specs/2026-08-11-v03-ship-design.md`

## Global Constraints

- **Frozen surfaces must not be edited under any circumstances:**
  `LANGUAGE_CARD.md`, `LANGUAGE_CARD_EXPLICIT.md`, the `OX0306`
  suggestion string, the `ARMS`/`arm` data keys, the `__oxide_` codegen
  prefix, the `.ox` extension, `eval/grammar/oxide.gbnf`. A card edit
  retokenizes every prompt and destroys comparability with all three
  campaigns this plan reports on.
- **Nothing under `eval/results/` may be modified.** Creating
  `eval/results/v03-synthesis/` is the only permitted touch there.
- **No `src/` changes.** This plan ships no language change. If a task
  seems to need one, stop and report BLOCKED.
- **No new measurement.** Every number must trace to committed data or a
  committed REPORT, cited to its source.
- **Never run `git add -A` or `git add .`** Two untracked directories,
  `eval/results/g0-generation-baseline/constrained/samples/` and
  `.../unconstrained/samples/`, predate this work and must stay
  untracked. Stage explicit paths only.
- Commit messages carry **no Claude/AI attribution** and follow
  conventional commits (`docs:` for every commit in this plan).
- Use `.venv/bin/python`, not the system `python` (no pytest there).

- [ ] **Step 3: Write the REPORT**

Required sections, in order:

1. **Header.** State plainly that this directory holds **no
   `cells.jsonl` of its own** — it is a synthesis over three committed
   campaign roots, which it names with their run prefixes (`g0c`, `g1c`,
   `v03c`). It is the first non-campaign entry under `eval/results/`, so
   a reader must not go looking for raw data that is not there.
2. **What v0.3 was.** §55, §56, §57 — each selected from a measured
   friction in the G0 corpus, not proposed from taste. Note explicitly
   that the version number was originally allocated to the ownership
   inversion that SPEC §32 item 3 records as REJECTED.
3. **The finding: one change did the work.** Lead with the first-compile
   table (it is the metric an ergonomic fix acts on; passing also
   requires correct logic, which no syntax change supplies), including
   the demand column and the dose-response. Then the first-pass table.
   Then the 87% and 79% figures.
4. **Controls.** Both tables above. Call out that the **explicit** arm is
   the more informative control: it receives all three changes
   identically, as they are core front-end changes both dialects
   inherit, and does not move — reproducing on generation the same split
   the repair probe found for §53.
5. **What §56 and §57 bought instead of rate.** §56: deformation 18 → 0,
   plus the intermediate-segment defect class (`o.i.clone().n = 5`), the
   only class found in this project that **rustc accepts** and so
   escapes the oracle. §57: 0 of 9 carrier programs compiled pre-change
   and 0 of 11 after; true effect on first-compile bounded at **0.0pp**,
   not merely below the floor.
6. **The conclusion.** §55 bought a mean +1.83pp first-pass; §56+§57
   bought +0.5pp for more implementation and review work. Combined with
   §57's mechanical null — resolution-stage ergonomics sit downstream of
   where these models actually fail — the ergonomics loop has reached
   diminishing returns. This is the measured basis for the pivot to
   SPEC §32.4, for which `v03c` is the comparison point.
7. **A caution that must not be omitted.** At v0.3 HEAD the paired
   oxide − explicit **generation** first-pass deltas are qwen +9.0pp
   (SE 6.8), codegemma +4.5pp (SE 3.7), granite +1.0pp (SE 4.6) — **none
   clears 2 SE**. The project's headline ownership result is a *repair*
   result. State the distinction explicitly; this is the document where
   the two meet and a reader must not be able to conflate them.
8. **What this does not show.** One shot condition, one 20-task corpus,
   SPEC §47's ±5pp floor. §56 and §57 landed in a single campaign and
   **cannot be separated by it** — every joint figure is joint. granite
   carries its 4096-window covariate throughout. No new data was
   collected for this document.
9. **Sources.** The three roots, the three commands, and the committed
   REPORTs this document defers to.

Do **not** restate the closing-baseline REPORT's endpoint scorecard,
comparability statement, provenance table, four-hour method note, or its
two VACUOUS endpoints. Cite `eval/results/v03-closing-baseline/REPORT.md`
for those. Duplicating them creates two copies that can drift.
